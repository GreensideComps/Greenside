# Greenside Competitions

UK golf prize-competition business, pre-launch. Positioning: **Premium Prizes. Affordable Entries.**
Commercial goal right now: maximise qualified email signups, then convert them to competition entrants.

## What this repo is

A mirror of the **live Shopify theme**, kept in git for version control and review. It is not the
source of truth for the live site — Shopify is. Changes here only reach customers once the theme is
published in Shopify admin.

Theme: Horizon-based, Online Store 2.0. Homepage sections live in `templates/index.json` and are
mostly self-contained blocks in `blocks/` (`ai_gen_block_*.liquid` were generated by Shopify's AI
section builder; `how-it-works.liquid` and `waitlist-momentum.liquid` were hand-written).

## Deployment constraint — read before promising anything ships

The Shopify MCP **blocks writes to the live/MAIN theme and blocks theme publishing.** An agent can:

- write theme files to **unpublished** themes (`themeFilesUpsert`)
- duplicate a theme (`themeDuplicate`)

An agent **cannot** publish, or edit the live theme. Getting anything live requires Ben to act in
admin. So: stage changes in an unpublished preview theme, then hand over.

Previewing an unpublished theme needs a staff session. `?preview_theme_id=<id>` silently returns the
**live** page to an unauthenticated fetch (identical byte size is the tell) — so an agent cannot
render-verify staged work. Say so rather than implying it was visually checked.

## How email capture works

`snippets/greenside-signup-modal.liquid`, rendered globally from `layout/theme.liquid`. Opens on any
element with `[data-greenside-signup-trigger]`. Posts straight to Klaviyo's public client
subscriptions API — no backend, no Klaviyo onsite JS. Sets explicit email marketing consent.

Phone is captured and normalised to E.164 but SMS consent is deliberately **not** set
(`SMS_SENDER_CONFIGURED = false`) because no SMS sender is verified in Klaviyo. Don't flip that flag
until one is.

Klaviyo's client API response is often unreadable by the browser even though the write succeeds, so a
network-level failure intentionally shows success. That's empirically correct, not a bug.

## Verified gotchas

- **`shopify://` URLs do not resolve in raw HTML.** They only work in link/url theme settings. The
  footer's custom Liquid used `href="shopify://pages/..."` and rendered dead links on the live site.
  Use `{{ pages['handle'].url }}` in markup instead.
- Theme `range` settings reject a `default` that isn't a whole number of `step`s from `min`. Shopify
  rejects the whole file with "default must be a step in the range".
- Header nav uses the `greenside-main-menu` menu, whose items are `#shopify-section-<id>` anchors.
  Those IDs change if a section is recreated in the theme editor, silently breaking the nav. The
  default `main-menu` (with its empty "Catalog" link) is not displayed.
- Klaviyo MCP: `filter` on list/flow `id` only supports `any(...)`, not `equals(...)`.

## Current state (verified 2026-09-12)

Live and publicly reachable — **password protection is off**. It is a waitlist landing page:
0 products, 1 collection, 0 orders, 2 Klaviyo subscribers.

Working: the landing page, consented email capture, Klaviyo↔Shopify integration, published Privacy
Notice and Terms & Conditions, footer with socials.

Homepage copy is deliberately honest about pre-launch status ("will", "planned"). **Keep it that
way** — do not write copy implying competitions are already running, or invent testimonials,
winners, or subscriber counts. There are no customers yet, so there is no social proof to report.
`waitlist-momentum.liquid` shows a count only when Ben sets one, and falls back to count-free copy at 0.

### Blocking launch

1. **No authenticated sending domain in Klaviyo** (`sending-domains` returns empty). The welcome
   email has **never sent to anyone** — 0 received, 0 skipped, so no send was ever attempted.
   Needs DNS records; Ben's action. Until then, email cannot be relied on.
2. **No competition products exist**, so entry/pricing presentation, competition pages and the
   checkout journey do not exist and have never been tested.
3. **Competition mechanics undecided** — skill question / free entry route, winner selection,
   closing dates, per-competition T&Cs. UK prize-competition law question, not a design one.
4. **Promises with no mechanism.** The live page commits signups to "double entries", "referral
   rewards" and Founding Member tiers. Nothing records or honours these yet.
5. **No conversion tracking.** Shopify's built-in analytics covers sessions and source; Klaviyo
   counts signups. Everything downstream of checkout is unmeasurable until products exist.

### Deliberately deferred

GA4/pixels (revisit when actively driving traffic), Klaviyo onsite JS and browse abandonment,
abandoned-checkout and order-confirmation flows (impossible without products), removing the unused
Judge.me app, replacing the fragile nav anchors.

## Operating principles

Get a credible, trustworthy, measurable version live and learn from real customers. Don't add apps,
AI features, infrastructure or complexity without a reason. Don't redesign what's good enough.
Prefer simple and reliable. Separate MUST FIX BEFORE LAUNCH from CAN IMPROVE AFTER LAUNCH.
